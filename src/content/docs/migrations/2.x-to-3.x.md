## About the release

Version 3.0 restructures the package entrypoints, makes GraphQL mocking link-first, and unifies the handling of unhandled requests and WebSocket connections. This guide will help you migrate your application to version 3.0. **We highly recommend you read it from start to finish.**

> Make sure to read the official announcement for this release if you've missed it!

## Breaking changes

### Environment

#### Node.js version

**This release sets the minimal supported Node.js version to 22.0.0.**

::: warning
  **Node.js versions prior to Node.js 22 are no longer supported.** To use the
  next versions of MSW, please migrate to Node.js 22 or higher.
:::

### Imports

The request and event handlers, as well as the utility functions, are now exported from designated entrypoints of the `msw` package instead of its root.

**Before:**

```js
import {
  http,
  HttpResponse,
  graphql,
  ws,
  sse,
  delay,
  bypass,
  passthrough,
} from 'msw'
```

**After:**

```js /msw\/http/ /msw\/graphql/ /msw\/ws/ /msw\/sse/ /msw\/utils/
import { http, HttpResponse } from 'msw/http'
import { graphql } from 'msw/graphql'
import { ws } from 'msw/ws'
import { sse } from 'msw/sse'
import { delay, bypass, passthrough } from 'msw/utils'
```

Use this table to find the new entrypoint for each export:

| Export                                                   | 2.x   | 3.x           |
| -------------------------------------------------------- | ----- | ------------- |
| `http`, `HttpResponse`                                   | `msw` | `msw/http`    |
| `graphql`                                                | `msw` | `msw/graphql` |
| `ws`                                                     | `msw` | `msw/ws`      |
| `sse`                                                    | `msw` | `msw/sse`     |
| `delay`, `bypass`, `passthrough`, `isCommonAssetRequest` | `msw` | `msw/utils`   |

The `setupWorker` and `setupServer` functions are still exported from `msw/browser` and `msw/node` respectively.

### GraphQL

#### Link-first mocking

GraphQL mocking is now _link-first_. The `graphql.query()`, `graphql.mutation()`, and `graphql.operation()` methods have been removed from the `graphql` namespace.

**Before:**

```js
import { graphql, HttpResponse } from 'msw'

export const handlers = [
  graphql.query('GetUser', () => {
    return HttpResponse.json({
      data: {
        user: { name: 'John' },
      },
    })
  }),
]
```

**After:**

Create a [GraphQL link](/api/graphql#graphql-link-url) for the endpoint you wish to mock via `graphql.link()` and define the operation handlers on that link instead.

```js /graphql.link/ {4,7}
import { HttpResponse } from 'msw/http'
import { graphql } from 'msw/graphql'

const api = graphql.link('https://api.example.com/graphql')

export const handlers = [
  api.query('GetUser', () => {
    return HttpResponse.json({
      data: {
        user: { name: 'John' },
      },
    })
  }),
]
```

> If your application talks to a single GraphQL endpoint, use its URL (relative or absolute) as the link. You can also use wildcards and regular expressions as the `url` argument of the link.

### `onUnhandledRequest`

The `onUnhandledRequest` option of `worker.start()` and `server.listen()` has been renamed to `onUnhandledFrame`. It now applies to any unhandled _network frame_, which includes both requests and WebSocket connections.

**Before:**

```js
server.listen({
  onUnhandledRequest: 'error',
})
```

**After:**

```js /onUnhandledFrame/
server.listen({
  onUnhandledFrame: 'error',
})
```

#### Custom callback

The custom callback no longer receives the `request` and `print` arguments. Instead, it receives a single object argument with the unhandled `frame` and the `defaults` strategies.

**Before:**

```js
server.listen({
  onUnhandledRequest(request, print) {
    if (request.url.includes('cdn.com')) {
      return
    }

    print.warning()
  },
})
```

**After:**

Check the `frame.protocol` to narrow down the frame type before accessing its data. Call the corresponding method on `defaults` to fall back to one of the built-in strategies.

```js /frame/ /defaults/ {2-3,7}
server.listen({
  onUnhandledFrame({ frame, defaults }) {
    if (frame.protocol === 'http' && frame.data.request.url.includes('cdn.com')) {
      return
    }

    defaults.warn()
  },
})
```

> Learn more about the [`onUnhandledFrame`](/api/setup-server/listen#onunhandledframe) option.

### Life-cycle events

#### `connection` event

The `connection` life-cycle event has been renamed to `websocket:connection`.

**Before:**

```js
server.events.on('connection', listener)
```

**After:**

```js /websocket:connection/
server.events.on('websocket:connection', listener)
```

### `worker.stop()`

The `worker.stop()` method now returns a `Promise<void>` that resolves once the request interception has been disabled for the current client. Make sure to await it.

**Before:**

```js
worker.stop()
```

**After:**

```js /await/
await worker.stop()
```

### `handleRequest()`

The `handleRequest` utility function has been removed. Use the [`getResponse()`](/api/get-response) function to resolve a request against a list of request handlers, or the experimental [`defineNetwork()`](/api/experimental/define-network) API to define a custom network.

## New API

In addition to the breaking changes, this release introduces a list of new APIs.

### GraphQL subscriptions

Building on top of the WebSocket interception, MSW now supports mocking GraphQL subscriptions. Use the `.subscription()` method on a GraphQL link to intercept a subscription and publish data to the subscribers via the `subscription` object exposed on the response resolver.

```js /subscription/ {6-13}
import { graphql } from 'msw/graphql'

const api = graphql.link('https://api.example.com/graphql')

export const handlers = [
  api.subscription('OnCreateMessage', ({ subscription }) => {
    subscription.publish({
      data: {
        messageCreated: {
          content: 'Welcome, subscriptions!',
        },
      },
    })
  }),
]
```

### `websocket:error` life-cycle event

A new `websocket:error` life-cycle event is emitted whenever an intercepted WebSocket connection errors. This includes both the initial connection errors and the errors that happen after the connection has been established.

```js /websocket:error/
server.events.on('websocket:error', ({ url, protocols, error }) => {
  console.log('WebSocket connection to %s errored!', url.href)
  console.error(error)
})
```

### Vite plugin

MSW now ships a designated Vite plugin under `msw/vite`. The plugin serves the worker script for you, so you no longer have to copy the `mockServiceWorker.js` script into your public directory.

```js /msw\/vite/ {2,5}
import { defineConfig } from 'vite'
import { msw } from 'msw/vite'

export default defineConfig({
  plugins: [msw()],
})
```

The plugin also provides a preconfigured `network` instance via the `virtual:msw` module, which you can use to enable mocking in your application.

```js /virtual:msw/ {2,5-6}
if (import.meta.env.DEV) {
  const { network } = await import('virtual:msw')
  const { handlers } = await import('./mocks/handlers')

  network.configure({ handlers })
  await network.enable()
}
```
